# حور | HOUR ABAYAS

متجر عبايات نساء وأطفال عربي RTL بخط IBM Plex Sans Arabic وNoto Naskh Arabic وعلامة عباية متجهية، مبني بواجهة React وخادم Express وtRPC وقاعدة PostgreSQL على Neon، مع تخزين صور في Vercel Blob. الموقع منشور على Vercel؛ لا توجد منتجات أو طلبات تجريبية، ووسائل الدفع الإلكترونية معروضة كخيارات مستقبلية مقفلة.

## الحالة وما يلزم قبل البيع

- يعرض المتجر منتجات قاعدة البيانات الحقيقية فقط؛ عند عدم وجود منتجات تظهر حالة فارغة بدل صور أو بيانات وهمية.
- لوحة الإدارة على `/admin` تستخدم اسم مستخدم وكلمة مرور تضبطهما في متغيرات Vercel. لا تحتاج إلى Manus OAuth أو Callback أو `OWNER_OPEN_ID`.
- يجب إعداد `ADMIN_USERNAME` و`ADMIN_PASSWORD` و`MANUS_JWT_SECRET` ضمن **Project Settings → Environment Variables** ثم إعادة النشر. يلزم أن يكون `MANUS_JWT_SECRET` بطول 32 محرفًا على الأقل. لا تضعي أي قيمة سرية في Git أو في متغير `VITE_*`. تدوم جلسة الإدارة سبعة أيام، ويؤدي تغيير بيانات الدخول إلى إبطال الجلسات الحالية.
- اربطي `NEON_DATABASE_URL` بقاعدة Neon PostgreSQL المقصودة؛ يقبل الخادم أيضًا `DATABASE_URL` عند توفيره من تكامل Vercel. اتصال Manus MySQL ليس بديلًا عن Neon في هذا التطبيق.
- عند تفعيل خريطة التوصيل، أضيفي `GOOGLE_MAPS_BROWSER_KEY` إلى متغيرات Vercel ثم أعيدي النشر. المفتاح يُرسل إلى المتصفح لتشغيل Maps JavaScript API، لذلك ليس سرًا؛ قيّديه في Google Cloud بـ **Maps JavaScript API** وبإحالات HTTP لنطاق الإنتاج `https://hour-abayas-makkah.vercel.app/*` وأي نطاق مخصص مستخدم، ولا تفعّلي APIs أخرى إلا عند الحاجة.
- يلزم ربط مخزنين منفصلين من Vercel Blob: `PRODUCT_BLOB_READ_WRITE_TOKEN` لصور المنتجات العامة، و`REVIEW_BLOB_READ_WRITE_TOKEN` لصور التقييمات الخاصة.
- قبل استقبال الطلبات، أضيفي منتجات حور الحقيقية وصورها وأسعارها ومخزون كل مقاس وروابط التواصل، وتحققي من رسوم التوصيل ومتطلبات النشاط التجاري. التوصيل داخل مكة يبدأ من 15 ر.س. وقد تزيد الرسوم حسب المسافة؛ والاستلام من المنزل مجاني.
- الدفع الإلكتروني غير مفعّل. راجعي شروط الاستضافة الحالية والاستخدام التجاري والتكاليف لدى مزودي الخدمات قبل بدء البيع.

## إعداد Vercel

1. اربطي مستودع GitHub الحالي بمشروع Vercel واستخدمي مجلد المشروع بوصفه جذر المشروع.
2. يضبط `vercel.json` أمر البناء `pnpm build:vercel` ومجلد النشر `public`. ينشئ الأمر `dist/vercel-entry.js` كحزمة ESM تضم وحدات Express، وتعيد وظيفة `api/index.js` تصديرها لمسارات `/api/*`. يعيد إعداد المسارات صفحات `/admin` و`/women` و`/kids` و`/product/:id` و`/cart` و`/checkout` و`/404` إلى واجهة الموقع كي تعمل عند فتح الرابط مباشرة.
3. أضيفي متغيرات البيئة المطلوبة إلى بيئات Vercel المناسبة. يوضح `.env.example` أسماء المتغيرات فقط ولا يحتوي على أسرار حقيقية.
4. لتشغيل الخريطة، أضيفي `GOOGLE_MAPS_BROWSER_KEY` في Vercel وقيّديه بالنطاق وMaps JavaScript API كما أعلاه، ثم أعيدي النشر. إذا لم يُضف المفتاح، يبقى إدخال العنوان اليدوي متاحًا.
5. راجعي ملفات الترحيلات الموجودة. لا تشغّلي الترحيلات على قاعدة الإنتاج المشتركة لمجرد اختبار التطبيق. قبل نشر التعديلات الجديدة، شغّلي `scripts/neon-migration-0003.sql` مرة واحدة في SQL Editor لقاعدة Neon المستخدمة فعليًا؛ الملف يضيف أعمدة وإعلانًا وفهرسًا ولا يحذف بيانات.

## ترحيلات Neon والبيانات

- لإنشاء ملفات SQL من المخطط المحلي: `pnpm db:generate`. يستخدم الأمر عنوانًا وهميًا عند عدم وجود `NEON_DATABASE_URL` ولا يكتب إلى أي قاعدة.
- أمر تطبيق الترحيلات محمي ويتطلب PostgreSQL صالحًا وموافقة بيئية صريحة: عيّني `CONFIRM_NEON_MIGRATIONS=1` بعد مراجعة عنوان الهدف ثم شغّلي `pnpm db:migrate`.
- لا تشغّلي الترحيلات على قاعدة إنتاج مشتركة للاختبار؛ استخدمي مشروع/قاعدة معاينة منفصلة بعد مراجعة النسخة الاحتياطية وسياسة الاحتفاظ بالبيانات.
- لا تُخزَّن المنتجات أو الطلبات في `localStorage`. السلة مؤقتة في ذاكرة التبويب، وقد تُفرغ عند إعادة تحميل الصفحة.
- يعيد الخادم التحقق من الأسعار والمقاسات والتوفر عند إنشاء الطلب؛ يبقى الطلب جديدًا دون حجز المخزون إلى أن يؤكده المدير، وعندها يعاد التحقق ويخصم المخزون داخل معاملة PostgreSQL. عند إلغاء طلب مؤكد يعاد المخزون في معاملة واحدة. لا يمكن إعادة فتح الطلب الملغي أو المكتمل، ولا تعديل أو حذف منتج مرتبط بطلب نشط.
- لا يتحول إتمام الطلب إلى واتساب. بيانات الطلب تحفظ في Neon وتظهر للمدير المخوّل فقط. رسوم التوصيل الأساسية 15 ر.س. وقد يحدد المدير زيادة حسب المسافة؛ الاستلام مجاني.
- مع إعداد المفتاح، تختار العميلة نقطة التوصيل على Google Maps وتُحفظ إحداثياتها مع العنوان؛ تظهر للمدير كرابط خريطة. يسمح إدخال العنوان اليدوي عند غياب المفتاح أو تعطل الخريطة، ويجب على المدير مراجعة أنه داخل نطاق توصيل مكة قبل التأكيد. لا يفرض التطبيق مضلعًا جغرافيًا آليًا قبل تحديد حدود الخدمة من المتجر.
- تدير لوحة الإدارة الإعلانات: إعلان واحد نشط كحد أقصى؛ عنوان ونص وصورة ورابط اختيارية، ويظهر للزائرة مرة واحدة في الجلسة. لا يظهر محتوى افتراضي عند غياب إعلان نشط.
- قائمة مدى والبطاقات وApple Pay وSTC Pay توضيحية فقط ومقفلة. لا يجمع الموقع بيانات بطاقة ولا يعالج أو يحصّل دفعات.
- المراجعات غير منشورة حتى يعتمدها المدير. تُرفع صور التقييم إلى مخزن Blob الخاص عبر الخادم بعد فحص النوع والحجم، ولا تظهر الصورة المعلقة للعامة. حصص الرفع وحماية الطلبات تحفظ بصمات HMAC بدل IP أو رقم الهاتف الخام.

## التطوير والفحوصات

يتطلب Node.js وpnpm المتوافقين مع `package.json` و`pnpm-lock.yaml`.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

أوامر الفحص والبناء:

```sh
pnpm check
pnpm test
pnpm build:vercel
```

ينتج البناء المحلي ملفات الواجهة الثابتة داخل `public/`؛ وهي ناتج مولّد ومتجاهل في Git. قد لا تتصل معاينة Manus بخدمات Neon وBlob المهيأة في Vercel، وعندها تعرض الواجهة حالات الإعداد أو الكتالوج الفارغ ولا تحفظ طلبات.
